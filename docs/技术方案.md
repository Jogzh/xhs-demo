# 小红书自我迭代 Agent 技术方案（v2.0 改版）

> 版本：v2.0（2026-10-11）
> 前身：xhs-demo 单文件脚本（`xhs.py`，Playwright persistent context 抓取+发布，已实测跑通）
> 参考：`D:\Desktop\py_proj\xhs-agent`（SQLite/调度/数据回流/AGENTS.md 体系）
> 目标：把"能发文章"的单文件脚本，升级为 **能自己 loop 起来的自我迭代 Agent**——
> 选题调研 → 写内容 → 发布 → 数据回流打分 → 复盘出策略 → 反哺下一篇，每日自动执行。

---

## 1. 本次改版要解决的问题

| 旧版（xhs.py 单文件） | 新版（xhs_agent 包） |
|---|---|
| 只能手动一条条跑命令 | 计划任务每日自动 loop（发布 10:30 / 回流 09:05） |
| 发完就忘，没有数据 | metrics 快照入库，score 评分，T+7 结题 |
| 写作无依据 | research 调研爆款 → 摘要给 AI 参考 |
| 无记忆 | insights 策略库：高分/低分对比结论滚动积累 |
| 截图散落根目录 | 每次运行产物归档 `data/runs/<时间戳>/` |
| 无开关、无幂等 | settings 总开关秒级生效；runs 表同日同 kind 仅一次成功 |
| cookie 方案（xhs-agent 教训） | **persistent context**：扫码一次，登录态落 `user_data/`，永不手抄 cookie |

**继承 xhs-demo 的关键决策**：所有浏览器操作走同一个 Playwright **持久化上下文**
（`launch_persistent_context(user_data/)`）。xhs-agent 用 `.env` 手抄 cookie 的方案
已暴露痛点（cookie 过期要人工更新）；持久化上下文由浏览器自己维护会话，且
`--disable-blink-features=AutomationControlled` + 真实 UA 降低风控概率。

## 4. 模块设计

### 4.1 browser.py —— 统一浏览器层（一切的地基）

- `Browser(headless)` 上下文管理器：`launch_persistent_context(user_data)`，
  固定视口 1400×900（发布按钮坐标点击依赖此值）、zh-CN、Asia/Shanghai、反自动化参数。
- **账号锁（2026-10-12 风控事件后加）**：settings 表 `account_lock=on` 时
  `Browser.__enter__` 直接抛 `AccountLockedError`——任何命令都无法启动登录态浏览器，
  防止风控观察期内误碰账号。`lock-account` / `unlock-account` 命令切换。
- `has_login(ctx)`：检查 `web_session` cookie。
- `detect_rate_limit(page)`（模块级函数，登录态/无痕通用）：标题/URL 含
  "安全限制 / 300012 / website-login/error"即抛 `RateLimitError`——所有页面导航后必须调用。
- 每次运行只起一个浏览器实例（persistent context 同一时刻仅允许一个进程使用）。

### 4.2 search.py / fetch.py —— 读操作

- `search(keyword, top_n)`：打开 `/search_result?keyword=...`，DOM 提取
  `section.note-item` → `{note_id, xsec_token, title, author, like}`（20~30 条/次）。
- `note_detail(note_id, xsec_token)`：`__INITIAL_STATE__.note.noteDetailMap` 提取
  全文/话题/互动/图片（沿用 xhs-demo 已验证的 JS 端挑字段方案，避开 Vue 代理序列化坑）。
- `fetch(urls)`：按链接抓整篇笔记存 `notes/<id>/note.md` + 图片/视频下载（保留旧能力）。

### 4.3 research.py —— 选题调研

输入主题 → search 取 top 20 → 按赞数挑 top 5 拉详情 → 生成爆款摘要
（标题句式/字数/emoji/数字、正文结构、话题分布、互动量级）：
- 写 `data/runs/<ts>/research.md`（给 AI 写作时直接引用）；
- 对标笔记入 `competitors` 表；
- **频率红线：一天最多调研 1 次**（调研=20+次页面访问，最接近风控阈值）。

### 4.4 cover.py —— 封面生成（零新依赖）

沿用 xhs-demo 的 HTML→截图方案（不引入 Pillow/字体问题）：
- `make_cover(lines, sub, kicker, account_tag)`：1080×1440 大字标题卡；
  2026-10-12 起为深色科技风（深蓝底＋青色辉光，原红渐变与 AI/科技定位不符，已换）。
- `make_list_card(title, rows)`：清单/步骤卡（浅底＋蓝色点缀，与封面同风格）。
- 浏览器上下文里 `set_content` 渲染截图（**不访问任何网站**，登录态/无痕上下文均可），
  产物进 `data/runs/<ts>/`；`render-images` 命令用无痕浏览器离线出图。

### 4.5 publisher.py —— 发布链路（核心资产，实测已通）

升级点（在原 cmd_post 基础上）：
1. 每步截图到 `data/runs/<ts>/`（01_open → 07_result），不再散落根目录；
2. 发布成功后从页面 URL/链接里抓 `note_id`（24 位 hex）返回，供 metrics 回流；
3. 正文末尾话题：`#话题` 触发下拉联想，尽力选中（失败保留纯文本 #）；
4. 保留成熟细节：从首页顶栏点"发布"进发布页、切"上传图文" tab、
   `keyboard.insert_text` 填正文、Escape 关话题联想、坐标点发布按钮（shadow DOM）、
   发布声明确认框处理、success 页检测；
5. `dry_run` 只到点发布前一步。

### 4.6 analytics.py —— 数据回流

- **登录态路径（默认，风控期停用）**：个人主页 `user/profile/<uid>`（uid 从浏览器
  cookie 的 `x-user-id` 取）→ 拿每篇笔记的 `xsec_token` → 详情页读互动数 →
  `save_metric` 快照 + 打分。T+7 自动结题（finished=1）。
- **无痕路径 `metrics --incognito`（2026-10-12 加）**：fresh context（无 cookie、
  不碰 user_data/）访问 `data/my_profile.txt` 里自己的主页 → 卡片拿点赞数
  （有 xsec_token 再进详情页拿全量互动）。预算 1 次主页 + 每篇 1 次详情页。
  **已知限制：网页端未登录访问主页是强制登录墙（302 /login），大概率采不到；
  采不到时数据靠用户报数或给笔记分享链接，AI 调 `fetch`（也无痕）补录。**

### 4.7 refresher.py —— 复盘（自我迭代的引擎）

- 已结题笔记按 score 排序，前 30% 为高分组、后 30% 为低分组；
- 规则对比：标题长度/是否含数字/emoji/疑问句、正文长度/结构标记、话题数；
- 差异写成结构化 insight 入 `insights` 表（scope/content/evidence/active）；
- `data/runs/<ts>/insights.md` 输出人可读版；
- AI 写 pending_note.json 时读 active insights 作为策略输入（AGENTS.md 约定）。

### 4.8 db.py —— SQLite（WAL）

沿用 xhs-agent 表设计，追加 `competitors`、`insights` 两表：

| 表 | 关键字段 | 用途 |
|---|---|---|
| settings | key, value, updated_at | master_switch 等热更新开关 |
| topics | name, status, last_used_at | 主题池轮询 |
| runs | run_date, kind, trigger, status, error | 审计 + 幂等（同日同 kind 一次 success） |
| notes | run_id, xhs_note_id, title, descr, strategy, published_at, score, finished | 我方笔记 |
| metrics | note_id, captured_at, day_offset, likes/collects/comments/shares | 互动快照 |
| competitors | keyword, note_id, title, author, likes..., raw_json | 调研对标 |
| insights | scope, content, evidence, active, created_at | 策略库 |

## 5. 命令面（`python -m xhs_agent <cmd>`，需 `PYTHONPATH=src`）

| 命令 | 作用 |
|---|---|
| `login` | 扫码登录，登录态存 user_data/（账号锁开着时拒绝） |
| `status` | 开关 / 排队内容 / 笔记得分 / 最近运行 / active insights |
| `pause` / `resume` | 总开关 off/on（计划任务全部跳过） |
| `search <关键词>` | 搜索打印 top 卡片（人工/调试用） |
| `fetch <链接>...` | 抓笔记存 notes/（保留旧能力） |
| `spy [--logged-in]` | 拆对标博主主页（清单 data/bloggers.txt） |
| `research [--topic X]` | 选题调研 → 爆款摘要 + competitors 入库 |
| `publish-content [--file F] [--dry-run]` | 发布 AI 排队内容（默认 data/pending_note.json）|
| `run-once --topic X [--dry-run]` | 模板兜底发布（无 AI 内容时） |
| `metrics [--incognito]` | 数据回流打分（无痕模式不碰账号） |
| `refresh` | 手动复盘出 insights |
| `daily` | 计划任务入口：只发排队内容，无则跳过（**不盲发**） |
| `render-images [--file F]` | pending 内容离线出图 + 发文文本（**用户手动发布用**，不访问小红书） |
| `lock-account` / `unlock-account` | 账号锁开关（风控期禁止一切登录态操作） |

## 6. 自迭代闭环怎么转（三种驱动方式）

1. **人机协作（主路径）**：在 ZCode 会话说"发文章"→ AI 按 AGENTS.md：
   选主题 → `research` 拿爆款摘要 → 结合 insights 写 `pending_note.json` →
   `publish-content` 发布 → 回报 note_id 和截图目录。
2. **全自动（排队模式）**：AI 随时写好 pending，10:30 计划任务自动发；
   09:05 自动回流打分；`refresh` 定期复盘出策略。
3. **兜底**：没排队内容又想保持日更 → `run-once --topic X` 用模板生成。

评分与迭代：`score = 1×赞 + 2×评 + 3×转 + 1.5×藏`（互动深度权重高于点赞），
T+1/T+3/T+7 三个观察点，T+7 结题进复盘池。

## 7. 安全护栏（实测红线，勿越）

1. **IP 风控 300012**：约 15 次自动化页面访问/小时触发"安全限制"，数小时自愈。
   日频设计在安全线内；**调试严禁反复跑**，research 一天 1 次。
2. **xsec_token**：详情页必须带搜索/主页卡片里的 token，随取随用不存储。
3. **每日最多发 1 篇**：runs 表幂等强制。
4. **persistent context 单实例**：浏览器实例互斥，跑脚本前确认没有残留 Chrome 进程占用 user_data/。
5. 发布前可 `--dry-run` 检查表单截图。
6. **风控观察期（2026-10-12 起，用户明令）**：账号被平台两次行为警告＋首篇笔记
   因「AI 托管」叙事被封禁＋第二篇（手动发）疑似限流。**一切登录态（user_data/）
   操作禁止**（账号锁 `account_lock=on` 强制）；**登录态自动发布永久放弃**
   （平台对"云端工具托管批量发布"直接封号，已处置 42 万账号）；发布全部改用户
   手动（AI 用 `render-images` 出内容+图片存本地）；复盘数据靠用户报数。
   当日项目数据重置重新开始（旧库归档 `data/app.db.bak_20261012`）。
   完整限流规则与出处见 [限流规避.md](限流规避.md)（同属护栏）。
   恢复登录态操作须用户明确同意（`unlock-account`）。
7. **内容红线**：标题/正文/封面严禁「AI 托管/AI 自动运营账号」叙事——平台明确
   判违规。安全框架 = 真人作者 + AI 工具（我实测/我用来做 X）。已入 insights 表。

**护栏之外皆可迭代（用户授权，2026-10-11）**：架构、模块划分、表结构、
模板文案、封面/清单卡视觉，发现问题随时重构，不受本方案初始设计束缚；
依据 = insights / 对标样本 / 运行证据，每次改动一个 commit 并写动机，
改完同步本文档与 AGENTS.md。上述红线不在此授权内。
